# Tauri migration validation

Candidate: 0.2.0, branch `codex/tauri-multiplatform`. Latest published release
remains v0.1.0. These results distinguish source review, compilation and runtime.

## Baseline and toolchain

- Baseline revision: `588e64b`, Windows-only v0.1.0.
- Baseline executable retained locally at `.tools/baseline/discard.exe`, with
  its GNU WebView2Loader.dll; never committed or installed over the existing app.
- Both Windows hosts use `%LOCALAPPDATA%\Discard\WebView2`; no cookie/session
  files were opened, moved, cleared or exported.
- Tauri 2.12.4, tauri-build 2.7.3, tauri-cli 2.12.3; transitive versions in Cargo.lock.
- Local toolchain: Rust 1.99.1, x86_64-pc-windows-gnu. Windows shipping target:
  x86_64-pc-windows-msvc via CI. Local MSVC linking is unavailable.
- CLI install: `cargo install tauri-cli --version 2.12.3 --locked`. Local CLI
  was obtained from the official tauri-cli-v2.12.3 release and its archive SHA256
  was compared with the GitHub release asset digest before extraction.

## Source and generated configuration review

`gen/schemas/capabilities.json` generated by tauri-build contains `{}`.
The application registers no invoke handler or application plugin. The remote
window receives no capability grant; `withGlobalTauri` is false. Windows native
configuration additionally disables host objects and web messages. This is a
source/configuration review, not a successful adversarial remote-IPC runtime test.

Main-frame navigation calls the existing pure URL parser policy. New windows
are denied and requested downloads return false. Subresource requests retain
browser handling, including Discord CDNs. No wildcard origin matching is added.

| URL case | Required result | Evidence |
| --- | --- | --- |
| `https://discord.com/app` | Allow | Existing parser rule retained; runtime pending |
| `https://discord.com/channels/@me` | Allow | Existing parser rule retained |
| `https://discord.com:443/app` | Allow | Effective-port rule retained |
| HTTP, port 444, embedded username/password | Deny | Existing scheme/port/credentials checks retained |
| `https://discord.com.evil.test`, `https://discord.com@evil.test` | Deny | Parsed exact hostname check retained |
| `file:`, `data:`, `javascript:`, localhost | Deny | HTTPS and exact hostname checks retained |
| Encoded hostname | Only if URL parsing normalizes to exact `discord.com` | URL-parser semantics; no prefix/string allowlist |

Unit/functional test suites were not run, in accordance with AGENTS.md. Manual
navigation/remote-frame adversarial probes remain unverified unless recorded below.

Task 2 source review found no need to change the existing URL policy. The Tauri
callbacks retain its exact rule, and generated capabilities are empty. The
Windows adapter fails closed if disabling native host objects/web messages fails;
background optimization failures alone remain nonfatal. Review does not establish
the outcome of a live remote-frame attack probe.

## Release blockers

Native runtime checks on macOS/Linux, real-account media checks, existing-session
upgrade validation and a fresh remote-content attack probe are not established.
No macOS signing/notarization credential has been configured by this migration.
Unsigned experimental macOS packages stay CI artifacts, outside ordinary public
release downloads. No new release has been published during local execution.
